## 審査で言う技術の芯（30秒）

1. アラーム作成で Agent の `schedule(発火時刻)` を登録する  
2. 発火で `status = fired` に `setState` → 接続中の画面へ自動配信  
3. 「起きた！」も同様に状態更新で作成者側へ反映  
4. **タブを開いておく前提**（Pushは切った。画面フルスクリーン警報で見せる）

言わない: 「D1に保存」「Web Pushで起こす」（実装していない）

## デモ手順（2ブラウザ）

1. A: グループ作成 → 招待コードを B に伝える  
2. B: コードで参加  
3. A: 「3分後」（または1分後）で B 向けアラーム作成  
4. 発火:
   - B: 赤いフルスクリーン警報 → 「起きた！」
   - A: 「○○さんの起床待ち」バナー（対象確認待ち）
5. A: ステータスが起床済みになり、バナーが消える  
6. （任意）確認しないままタイムアウト → A に「未確認のまま」バナー

失敗時: Pushの話をしない。両方タブを開き直して再接続。

## デモで触る UI（作成者側）

| 状態 | 画面 |
|------|------|
| `fired`（自分が作成者・相手が対象） | オレンジ系「起床待ち」バナー |
| `timed_out`（自分が作成者） | 赤系「未確認」バナー |
| 自分が対象の `fired` | フルスクリーン警報（バナーではない） |
